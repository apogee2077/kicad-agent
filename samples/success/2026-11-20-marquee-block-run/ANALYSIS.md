## 2. 逐颗 LED 验证

```
D1 (Red):    阴极K(1) -> GND    阳极A(2) -> R1.2    串联电阻=True
D2 (Green):  阴极K(1) -> GND    阳极A(2) -> R2.2    串联电阻=True
D3 (Blue):   阴极K(1) -> GND    阳极A(2) -> R3.2    串联电阻=True
D4 (Yellow): 阴极K(1) -> GND    阳极A(2) -> R4.2    串联电阻=True
```

完整网络：

```
+5V            ['J1.1', 'U2.3']                             输入 -> LDO 的 VI
+3V3           ['U2.2', 'U1.2', 'U1.3']                     LDO 的 VO -> ESP32 VDD / EN
GND            ['J1.2','U1.1','U1.15','U1.38','U1.39',
                'U2.1','C1.1','C1.2','C2.1','C2.2',
                'D1.1','D2.1','D3.1','D4.1']
LED_D1_GPIO    ['U1.10', 'R1.1']                            GPIO -> 限流电阻
LED_D1_A       ['R1.2', 'D1.2']                             限流电阻 -> LED 阳极
LED_D2_GPIO    ['U1.11', 'R2.1']
LED_D2_A       ['R2.2', 'D2.2']
LED_D3_GPIO    ['U1.12', 'R3.1']
LED_D3_A       ['R3.2', 'D3.2']
LED_D4_GPIO    ['U1.13', 'R4.1']
LED_D4_A       ['R4.2', 'D4.2']
```

## 3. 这次为什么成功

四个改动共同作用，缺一不可：

| 改动 | 作用 |
| --- | --- |
| **引入 `led` 积木** | LED 与限流电阻的串联拓扑由代码保证，模型不可能接错 |
| **BOM 提示词禁止列 LED/电阻** | 避免与积木重复，模型只需给出「哪几个 GPIO 驱动什么颜色」 |
| **重试次数 2 → 4（共 5 次）** | 第 1 次仍有错误，第 2 次通过 |
| **错误信息带引脚名** | 报错从「U2.2 同时接在两个网络」变成「U2.2（引脚名 VO）…」，模型能自我纠正 |

**关键证据**：本次模型输出被自动识别为

```
使用了 4 个电路积木：led, led, led, led
```

## 4. 遗留缺陷（本次仍未解决）

### C1、C2 两个电容被短路

```
GND: [..., 'C1.1', 'C1.2', 'C2.1', 'C2.2', ...]
```

两个电容的**两个引脚都在 GND 上**，两端同电位，等于短路，完全不起滤波作用。
正确接法应为：

- `C1` 跨接 `+5V` 与 `GND`（LDO 输入滤波）
- `C2` 跨接 `+3V3` 与 `GND`（LDO 输出滤波）

**为什么没被拦住**：`validate_design.check_design` 没有「器件所有引脚同属一个网络」
这条规则；KiCad 的 ERC 也不报（电气上无冲突，只是个无用的元件）。

### 其它简化之处（可接受但不理想）

- ESP32 的 `EN` 直接接 `+3V3`，没有 RC 复位网络
- 没有 BOOT 按键、没有下载电路
- 缺少 LDO 的输入/输出电容正确位置

## 5. 由此得出的下一步

| # | 改进 | 解决什么 |
| --- | --- | --- |
| 1 | 校验器增加「器件所有引脚在同一网络 = 短路」 | C1/C2 这类错误 |
| 2 | 增加 `ldo` 积木（AMS1117 + 输入/输出电容） | 稳压器与电容接法整段由代码保证 |
| 3 | 增加 `mcu_minimal` 积木（EN 复位 + BOOT） | 主控最小系统不用模型拼 |
