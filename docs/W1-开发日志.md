## 3. 电路设计：光闹钟

### 3.1 需求

> 到了预设时间就会控制 LED 灯组发光，亮度线性增长，在第 5 分钟时达到最大，
> 并同时开始播放音乐闹铃。

**两处歧义的处理**：

| 歧义 | 取值 | 理由 |
| --- | --- | --- |
| 音乐何时响 | 第 5 分钟（`audio_start: at_peak`） | 按字面"同时"指与"达到最大"同时；先光后声才是模拟日出 |
| "亮度线性" | 人眼感知线性（gamma 校正） | 占空比线性会导致前 4 分钟几乎无变化、最后一分钟突亮 |

亮度曲线：`duty(t) = (t / 300s) ^ 2.2`

### 3.2 架构

```
5V 输入 → 保险丝 → 防反接 → +5V ─┬─ 8×LED（各自 82Ω 限流）
                                  └─ AMS1117 → 3.3V ─┬─ ESP32-WROOM-32
                                                     ├─ DS3231M（I2C 硬件闹钟）
                                                     └─ OLED（I2C 接口）
ESP32 → PWM → AO3400A 低边开关 → LED 负极
ESP32 ⇄ UART ⇄ DFPlayer Mini 模块 → 扬声器
ESP32 ← INT ← DS3231M 闹钟（可深睡眠）
```

**关键决策**：用 DS3231M 的**硬件闹钟**（`~INT`）唤醒 MCU，而非软件轮询 ——
省电，且断电/复位后闹钟仍有效。

### 3.3 规模

48 个器件 / 28 个网络 / 128 个网络节点 / 25 个 no_connect。

### 3.4 功率预算

| 负载 | 典型 | 峰值 |
| --- | --- | --- |
| 8×LED | 184 mA | 184 mA |
| ESP32（关 WiFi） | 80 mA | 120 mA |
| DS3231M | 0.2 mA | 0.2 mA |
| DFPlayer Mini | 200 mA | 500 mA |
| **合计** | **≈ 0.47 A** | **≈ 1.3 A** |

选 5V/2A 适配器，保险丝 1.5A（低于此值会在音乐峰值误触发）。

### 3.5 已知不足

- LED 总功率仅约 0.9 W，作为"唤醒光源"偏弱（真实产品 5–20 W）
- 8 路 LED 共用一个 MOSFET，只能整体调光，无法分区依次点亮
- 音频依赖外购模块，非板载功放
- AMS1117 在 ESP32 WiFi 峰值下约 0.7 W 热耗，偏热

## 4. 原理图生成器

### 4.1 核心结论：作业原话不成立

作业写"用 KiCad 的 Python 脚本接口把 JSON 变成真实原理图"。实测：

```
> python -c "import eeschema"
ModuleNotFoundError: No module named 'eeschema'
```

KiCad 官方 Python API **只覆盖 PCB 侧（`pcbnew`）**，从未提供原理图编辑接口。

**改用路线**：`kiutils` 直接写 `.kicad_sch`（S-表达式）+ `kicad-cli` 做校验导出。

### 4.2 实现的能力

| 能力 | 文件 | 说明 |
| --- | --- | --- |
| KiCad 安装探测 | `kicad_env.py` | `KICAD_ROOT` → PATH → 常见目录，不写死路径 |
| 符号库加载 | `symbol_lib.py` | 显式 UTF-8 读取 + 派生符号展平 |
| 网表解析 | `sexpr.py` | 最小 S-表达式解析器 |
| 原理图写出 | `sch_writer.py` | 旋转、网络标签、自动选纸、PWR_FLAG |
| 端到端生成 | `generate.py` | 生成 → 导出网表 → **连通性分区比对** |
| 设计校验 | `validate_design.py` | 引脚存在性 / 短路 / 漏接 |

### 4.3 两个关键设计

**① 连接用网络标签，不画长导线**
GND 一个网络有 31 个节点，实体导线会变成蜘蛛网。做法：每引脚引出 2.54mm
短线（stub），末端放同名 `label`，KiCad 按名字合并网络。

**② 校验看"连通性分区"，不看网络名**
把设计和网表都表示成「引脚集合的集合」，两者必须完全相等。这样能抓出
"图画出来了但引脚没接上"这类静默错误 —— KiCad 本身不会报错。

### 4.4 验证结果（KiCad 10.0.8）

```
器件 51（48 实物 + 3 PWR_FLAG）  图纸 A3
stub 131  label 131  no_connect 25
设计网络 28 / 网表网络 28
连通性比对: PASS
ERC: 0 error / 2 warning
```

剩余 2 条告警：

| 告警 | 性质 |
| --- | --- |
| `lib_symbol_mismatch`（AO3400A） | 正常：展平派生符号后与库不一致 |
| `footprint_link_issues`（BT1） | 真问题：封装名 `BatteryHolder_Keystone_3001` 不存在，待修 |

## 5. 五步闭环

| 步 | 内容 | 实现 |
| --- | --- | --- |
| 01 | 环境搭建 | `kicad_env.py` / `catalog.py` 自检 |
| 02 | 自然语言 → BOM | `prompts/bom.md` + 符号白名单 `catalog.py` |
| 03 | 连接关系生成 | `prompts/connections.md` + **注入真实引脚表** |
| 04 | JSON → 原理图 | `sch_writer.py` + `generate.py` |
| 05 | 交互修正 | `prompts/revise.md` |

**关键设计：把引脚表塞进第 03 步的提示词**
程序从 KiCad 符号库实时查出每个器件的真实引脚，作为事实注入提示词。
模型最容易犯"凭记忆写引脚号"的错（DS3231 的 GND 是 5~13 脚、ESP32 的
IO21 是第 33 脚），注入后把"记忆题"变成"抄写题"。

**反馈闭环**：JSON 不合规 / 违反 schema / 用了白名单外符号时，
把具体错误回灌给模型重试（最多 2 次）。

**离线模式**：`--provider fixture` 用 `fixtures/*.json` 代替模型回答。
没有 key 也能跑通并做回归；接真 API 只换一个参数。

## 6. 交互修正实测

**需求**：「把 LED 灯全换成红色」

**关键点 —— 这不是纯文本替换**：

|  | 白光 | 红光 |
| --- | --- | --- |
| 正向压降 Vf | 3.0 V | 2.0 V |
| 电阻上余量 | 1.9 V | 2.9 V |
| 沿用 82Ω 时电流 | 23 mA | **35.4 mA（超标）** |

典型 0805 LED 额定 20~30 mA，35 mA 会缩短寿命。按目标 23 mA 重算：

```
R = (5.0 − 2.0 − 0.1) / 0.023 = 126 Ω  →  取 E24 标准值 130 Ω
实际电流 = 2.9 / 130 = 22.3 mA
```

**结果**：D3~D10 改为「红光 2.0V」，R8~R15 改为 130Ω；
器件数 48 不变，**网络拓扑完全未变**（换色不影响连接），连通性比对 PASS。

## 7. 关键技术决策汇总

| 决策 | 选择 | 备选 | 理由 |
| --- | --- | --- | --- |
| 时间源 | DS3231M 硬件闹钟 | ESP32 内部 RTC / 联网 NTP | 精度高、可深睡眠、断电不怕 |
| 原理图生成 | kiutils 写 S-表达式 | 官方 Python API | 官方根本没有 eeschema 接口 |
| 连接方式 | 网络标签 | 实体导线 | 31 节点 GND 无法用实体线排布 |
| 校验方式 | 连通性分区比对 | 只检查网表非空 | 后者抓不到"引脚脱开" |
| 输出格式 | KiCad 6 语法 `20211014` | 10 的 `20250114` | 保证 KiCad 8 也能打开 |
| 降压 | AMS1117 线性 | buck | 5V 输入压差小，线性够用 |

## 8. 踩过的坑与**被推翻的结论**

这一节最重要 —— 写报告时不要引用未经验证的因果。

### 8.1 真实的坑

**① 展平派生符号时没重命名嵌套 unit → 整份原理图"加载失败"**

`AMS1117-3.3` 是派生符号（`extends AP1117-15`），展平后内部 unit 仍叫
`AP1117-15_0_1`。KiCad 认不出该 unit 属于谁，**整份文件拒绝加载，且不给行号**。
修复：展平时把嵌套 unit 的 `entryName` 改成子符号自身名字。

**② kiutils 用系统 locale 编码读文件**

中文 Windows 是 GBK，遇到含非 ASCII 字符的符号库（如 `RF_Module`）直接
`UnicodeDecodeError`。修复：自行按 UTF-8 读文本，再交给 `from_sexpr` 解析。
同样的问题在**写文件**时也会出现，所以 `to_file()` 也改成了显式 UTF-8。

**③ `PWR_FLAG` 加错网络 → 新告警**

一开始给 `+5V/+3V3/GND` 都加，结果 `+3V3` 报 `pin_to_pin`
（U1 的 VO 本身就是 Power output，又加一个电源输出 → 冲突）；
同时漏了 `VBAT`，仍报 `power_pin_not_driven`。
正确集合是 `+5V`、`GND`、`VBAT`。

**④ 内容超出图纸**

48 个器件排出 381 mm 宽，A4 只有 297 mm，会有一截跑到纸外。
修复：按内容尺寸自动选纸（本例为 A3）。

### 8.2 **被推翻的旧结论**（早期判断有误）

| 旧结论 | 复测结果 |
| --- | --- |
| "`version` 必须与语法一致，否则 KiCad 拒绝加载" | **不成立**。`20211014` / `20231120` / `20250114` 三个版本号 `kicad-cli` 都能正常加载导出 |
| "元件实例必须用 `SymbolProjectInstance`，否则被拒" | **未复现**。`bisect_test.py` 的 5 种组合（有无 `id` / 有无 project 包裹 / 有无 sheet 实例）全部通过 |
| "机器上装的是绿色版/解压版 KiCad" | **错误**。有 `uninstall.exe` 和完整注册表记录，是安装版装完被移动了目录 |

> **教训**：当时同时改动多处，跑通后就归因给最后一个改动。这是典型的
> 错误归因。"改完能跑"不等于"这个改动解决了问题"。

### 8.3 其它记录

- `Effects(justify=None)` 会让 kiutils 序列化崩溃（内部直接调 `.to_sexpr()`）
- `Select-Object -First N` 会提前终止管道，导致被调用的程序被杀掉
- PowerShell 的 `@"..."@` here-string 里写 Python 的 `\"` 会语法错误
