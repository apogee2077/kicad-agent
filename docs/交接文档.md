## 1. 一句话说明

这是一个**用大语言模型把「一句话需求」变成 KiCad 原理图**的程序。
输入「设计一块光闹钟」，输出一张 KiCad 能打开的原理图，中间自动产出
器件清单（BOM）和引脚级连线的 JSON。

**它不做到 PCB 布线**，只到原理图。

## 2. 当前状态

| 项 | 状态 |
| --- | --- |
| 五步闭环（环境→BOM→连接→原理图→交互修正） | ✅ 全部跑通 |
| 真实模型端到端 | ✅ 已跑通（简单板子），复杂板子仍不稳 |
| 生成原理图 | ✅ 可生成、可打开、连通性可自动验证 |
| ERC | ⚠️ 光闹钟样板 0 error / 2 warning |
| PCB / DRC | ❌ 未做 |
| 12V 高压方案 | ❌ 只做了分析，未实施 |

**当前能稳定做到**：一句话生成 5~13 个器件的简单电路板，拓扑基本正确。

## 3. 从零开始：环境准备

### 3.1 必须安装的

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Python | 3.10+ | 开发用 3.13.7 |
| KiCad | 8.0+ | 开发用 **10.0.8**，装在 `D:\apps new\KiCad\10.0` |

### 3.2 安装步骤

```powershell
# 1. 克隆
git clone https://github.com/apogee2077/kicad-agent.git
cd kicad-agent

# 2. 建虚拟环境
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

# 3. 配置 KiCad 路径（装到默认位置可跳过）
#    如果 kicad-cli 不在 PATH 里，设 KICAD_ROOT 指向安装根目录
[Environment]::SetEnvironmentVariable('KICAD_ROOT', 'D:\apps new\KiCad\10.0', 'User')

# 4. 配置模型接口
copy .env.example .env
notepad .env      # 填入 LLM_API_KEY / LLM_BASE_URL / LLM_MODEL
```

### 3.3 关于模型接口（重要）

本机 `.env` 用的是**聚合网关**，不是 DeepSeek 官方：

```
LLM_BASE_URL=https://maas.qianwenaiapi.com/compatible-mode/v1
LLM_MODEL=qwen-plus
```

该网关没有 `deepseek-chat` 这个名字，填了会报 `404 Model not exist`。
可用的支持工具调用的模型（实测）：`qwen-plus`、`qwen3.7-plus`、
`deepseek-v4.1-flash`、`glm-5.3`、`kimi-k2.6`。

换模型只需改 `.env` 里的一行。

## 4. 怎么用

### 4.1 最简单：双击 `run.bat`

打开菜单，输入数字即可：

| 编号 | 功能 | 需要密钥 |
| --- | --- | --- |
| 1 | 环境自检（KiCad 是否装好） | 否 |
| 2 | 工具自检（三个工具函数） | 否 |
| 3 | 一句话生成电路板 | 是 |
| 4 | 修改已有设计（如把 LED 换红色） | 是 |
| 5 | 校验设计文件 | 否 |
| 6 | 打开 samples 目录看现成原理图 | 否 |

### 4.2 命令行（等价）

```powershell
cd "D:\File\202610AI大作业\个人\kicad-agent"

# 环境自检
.venv\Scripts\python.exe kicad_env.py

# 一句话生成
.venv\Scripts\python.exe agent.py design "设计一块 5V 指示灯板，3 颗 LED"

# 修改设计
.venv\Scripts\python.exe agent.py revise designs/light_alarm.json "把 LED 全换成红色"

# 只校验
.venv\Scripts\python.exe agent.py check designs/light_alarm.json

# 离线模式（不需要密钥，用 fixtures 里的预设答案）
.venv\Scripts\python.exe agent.py design "测试" --provider fixture
```

### 4.3 打开生成的原理图

产物在 `out/`：`design.json`（设计）和 `design.kicad_sch`（原理图）。

- **双击 `.kicad_sch`** 可直接用 KiCad 打开
- 想快速看效果，不用跑模型：打开 `samples/` 里现成的
- ⚠️ **看完不要保存** —— 一旦在 KiCad 10 里保存，文件会升级成 10 的格式，
  用 KiCad 8 的人就打不开了。要改就重跑脚本生成

## 6. 数据流

```
你说一句话
    │
    ▼  prompts/bom.md  + 符号白名单
[模型] ──> BOM.json（器件清单）
    │
    ▼  程序从 KiCad 符号库查出每个器件的真实引脚，注入提示词
    │
    ▼  prompts/connections.md + 引脚表 + 积木说明
[模型] ──> 连接.json（网络 + 积木调用）
    │
    ▼  积木展开成具体元件与网络（拓扑由代码保证）
    │
    ▼  电气校验（引脚存在性/短路/漏接），不合格 -> 带错误回灌重试（最多 5 次）
    │
    ▼  sch_writer.py 翻译成 .kicad_sch
    │
    ▼  kicad-cli 导出网表 -> 连通性分区比对
    │
PASS ──> 原理图可用于演示
```

**三道关卡**：

| 关卡 | 抓什么 | 漏什么 |
| --- | --- | --- |
| pydantic schema | JSON 结构、格式、单节点网络 | 电气合理性 |
| `check_design` | 引脚不存在、短路、漏接 | 器件内部短接（如电容两端同网络） |
| 连通性分区比对 | 图与设计是否一致 | **设计本身对不对** |

> **核心认知**：连通性比对 PASS 只说明"图忠实实现了设计"，
> **不说明设计是正确的电路**。这是两个层次的问题。

## 7. 已知问题（接手必读）

### 7.1 环境类

| 问题 | 现状 / 对策 |
| --- | --- |
| KiCad 版本 | 课程要求 KiCad 8，实际用 10.0.8。生成的是 v6 语法，8/9/10 都能读；**但 GUI 保存会升级格式**，导致 8 打不开 |
| `git` 在本会话需提权 | 沙箱限制，正常终端无此问题 |
| PATH 不生效 | 环境变量只对新进程生效；改完要重开终端 |

### 7.2 模型类

| 问题 | 现状 / 对策 |
| --- | --- |
| 模型会编造符号名 | `catalog.py` 白名单拦截 |
| 模型会凭记忆写引脚号 | 注入实时引脚表，把记忆题变抄写题 |
| 模型会产生概念性错误（如电阻接错） | **重试无效**，只能靠积木把拓扑写死 |
| 结果偶发不稳定 | 已设 `temperature=0`；仍非 100% 确定 |

### 7.3 设计/生成类

| 问题 | 状态 |
| --- | --- |
| **电容两端接在同一网络（短路）** | ❌ 校验器抓不到，需增加规则 |
| 积木只有 `led` 一种 | ❌ 缺 `ldo`、`button`、`i2c`、`mcu_minimal` |
| 光闹钟 ERC 有 2 条 warning | ⚠️ 1 条是展平符号的正常告警；1 条是 BT1 封装名不存在，待修 |
| 原理图为"标签式"画法 | ⚠️ 每引脚一小段线 + 网络名，非实体走线；可读性一般 |
| 复杂板（48 器件）未经真实模型验证 | ⚠️ 只用离线 fixture 跑过 |

## 8. 关键决策与原因（答辩会被问）

| 决策 | 选择 | 为什么不选另一个 |
| --- | --- | --- |
| 原理图怎么生成 | `kiutils` 直接写 `.kicad_sch` | KiCad 官方**没有** eeschema 的 Python API，只有 PCB 侧的 `pcbnew` |
| 连接怎么画 | 网络标签，不画实体导线 | GND 一个网络 31 个节点，实体线会乱成蜘蛛网 |
| 怎么验证正确 | 导出网表做「连通性分区比对」 | 只看"有没有网表"抓不到引脚脱开 |
| 输出文件版本 | 固定 KiCad 6 语法 `version 20211014` | 保证 KiCad 8 也能打开 |
| 怎么防模型接错 | **预验证积木**（借鉴 CircuitAgent） | 纯提示词描述拓扑，实测三次重试仍复发 |
| 降压方案 | AMS1117 线性 | 5V 输入压差小，线性够用；12V 才需要 buck |

## 10. 接手后第一步该做什么

按优先级：

1. **先验证环境没坏**：双击 `run.bat` → 选 1、选 2，都应有正常输出
2. **看一眼现成成果**：选 6 打开 `samples/success/` 里的原理图
3. **读两份历史**：
   - `docs/开发日志.md` 第 8 节（被推翻的结论，避免重复踩坑）
   - `samples/failures/.../ANALYSIS.md`（失败长什么样）
4. **接着做这三件**（按性价比）：
   - 校验器加「器件所有引脚同网络 = 短路」
   - 增加 `ldo` 积木
   - 增加 `mcu_minimal` 积木（EN 复位 + BOOT 电路）

## 11. 故障排查

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 找不到 KiCad | PATH 没有 `kicad-cli` | 设 `KICAD_ROOT` 指向安装根目录 |
| `404 Model not exist` | 模型名在该网关不存在 | 改 `.env` 的 `LLM_MODEL`，见 3.3 |
| `401 Unauthorized` | 密钥错误或过期 | 检查 `.env` 的 `LLM_API_KEY` |
| `[第 N/5 次尝试]` 反复出现 | 模型输出不合规，正在自动重试 | 正常现象；若 5 次都失败会中止 |
| 输出里有乱码 | 控制台编码 | `run.bat` 已设 UTF-8；命令行运行需 `chcp 65001` |
| 原理图打不开 | `.kicad_sch` 无文件关联 | 用 `eeschema.exe` 的"文件→打开"，或拖进 KiCad 窗口 |
| 生成很慢 | 在等模型响应，或触发重试 | 1~5 分钟属正常 |
| `连通性比对: FAIL` | 生成器没把图画对 | 这是真 bug，查看输出里的缺失/多余网络清单 |
