# 光闹钟设计说明

> 配套文件：`designs/light_alarm.json`（BOM + 网络，机器可读）
> 校验：`python validate_design.py designs/light_alarm.json`

---

## 1. 需求原文

> 到了预设时间就会控制 LED 灯组发光，亮度线性增长，在第 5 分钟时达到最大，
> 并同时开始播放音乐闹铃。

### 两处歧义及处理

| 歧义 | 两种理解 | 本设计取值 | 怎么改 |
| --- | --- | --- | --- |
| 音乐何时响 | ① 第 5 分钟（光到最亮时）才响 ② 到点即响 | `at_peak`（第 5 分钟） | `params.audio_start` 改成 `at_start` |
| 「亮度线性」 | ① PWM 占空比线性 ② 人眼感知线性 | 感知线性（gamma 校正） | `params.brightness_curve` 改成 `linear_duty` |

**为什么把「亮度线性」理解成人眼感知**：人对亮度的感知接近幂律（约 1/2.2）。
占空比从 0 线性升到 100%，视觉上前 4 分钟几乎看不出变化、最后一分钟突然变亮，
这不是「渐亮」而是「突变」。要视觉上均匀变亮，占空比必须按幂律抬升：

```
duty(t) = (t / T) ^ γ        T = 300 s, γ = 2.2
```

t=150s 时占空比只有约 22%，符合「微弱起步」的预期。

## 2. 系统框图

```
     5V 输入
        │
   [F1 保险丝]──[D1 防反接]──┬── +5V ──┬── LED 灯组（8 路，各自限流）
        │                    │         │
        │                 [U1 AMS1117-3.3]  [Q1 AO3400A 低边开关]◄── PWM ──┐
        │                    │                                          │
        │                  +3V3                                         │
        │                    │                                          │
        │        ┌───────────┼───────────┬───────────┐                  │
        │        │           │           │           │                  │
        │     [U2 ESP32]  [U3 DS3231M] [J4 OLED]  [3×按键]              │
        │        │           │                                          │
        │        ├── I2C ────┘                                          │
        │        ├── INT ◄──── RTC 硬件闹钟（唤醒 MCU）                   │
        │        ├── PWM ────────────────────────────────────────────────┘
        │        └── UART ◄──► [J3 DFPlayer Mini] ──► 扬声器（直连模块）
        │
       GND
```

### 为什么这么选

| 决策 | 选型 | 理由 | 放弃了什么 |
| --- | --- | --- | --- |
| 时间源 | DS3231M（I2C，TCXO，±2ppm） | 用**硬件闹钟**触发 `~INT`，MCU 可深睡眠，比软件轮询省电且不怕复位 | ESP32 内置 RTC 精度差、联网 NTP 依赖 WiFi |
| 主控 | ESP32-WROOM-32 | 3.3V、LEDC 硬件 PWM（12 位）、I2C/UART 够用、后续可加 WiFi 对时 | 相比 STM32 更省外部器件 |
| 调光 | 单颗 AO3400A 低边 PWM | 8 路 LED 共用一个开关管，亮度同步；栅极 3.3V 可完全导通 | 无法分区调光 |
| 音频 | DFPlayer Mini 模块（4 针接口） | 板载 3W 功放，扬声器直连模块，免去自建功放与音频电路 | 依赖外购模块；非纯板载方案 |

> 音频做成**模块接口**而不是板载功放，是刻意的取舍：先把「灯 + 时序」这条主线做扎实，
> 音频属于可替换子系统。换成板载 ESP32 + I2S DAC + 功放是后续升级项。

## 3. 关键计算

### 3.1 LED 限流电阻

```
R = (V_supply − V_f − V_ds) / I
  = (5.0 − 3.0 − 0.1) / 0.023
  ≈ 82 Ω          → 取 82Ω，实测电流约 23 mA/路
```

- 8 路合计约 **184 mA**（全亮）
- 每路独立限流，避免 LED 并联分流不均

### 3.2 功率预算

| 负载 | 典型 | 峰值 | 备注 |
| --- | --- | --- | --- |
| LED 灯组（8 路） | 184 mA | 184 mA | 全亮 |
| ESP32（关 WiFi） | 80 mA | 120 mA | 用硬件闹钟时不需要 WiFi |
| ESP32（WiFi 发射） | — | 500 mA | 若启用联网对时 |
| DS3231M | 0.2 mA | 0.2 mA | |
| DFPlayer Mini | 200 mA | 500 mA | 播放峰值（含扬声器） |
| **合计（典型）** | **≈ 0.47 A** | **≈ 1.3 A** | |

- 选 5V/2A 适配器 → 裕量充足
- F1 自恢复保险丝选 **1.5A**（要高于峰值电流，否则播放音乐时误触发）

### 3.3 LDO 热耗

AMS1117-3.3 输入约 4.7V（经 D1 压降），输出 3.3V：

```
P = (4.7 − 3.3) × I_3v3
  = 1.4V × 0.12A ≈ 0.17 W     （关 WiFi）
  = 1.4V × 0.50A ≈ 0.70 W     （WiFi 发射峰值）
```

SOT-223 约 60°C/W，0.7W 时温升约 40°C，**可接受但偏热**。
量产版本应改用 buck（如 MP1584）或直接上 3.3V 输入。

## 5. 已知风险

1. **无分区调光**：8 路共用一个 MOSFET，只能整体调亮度，做不到「由暗到亮依次点亮」。
2. **DFPlayer 依赖外部模块**：模块质量、串口协议兼容性不可控。
3. **AMS1117 在 WiFi 峰值下偏热**（见 3.3）。
4. **未做 ESD / 浪涌防护**：USB/DC 入口没有 TVS，属于学习板级别的取舍。
5. **本设计尚未生成原理图**：48 个器件超出当前生成器能力（见 README「下一步」）。

## 6. 与生成器的衔接

这份设计是「LLM 应输出的目标格式」的样张。要把它真正变成 `.kicad_sch`，
生成器还缺三项能力：

| 缺失能力 | 为什么必须 | 影响范围 |
| --- | --- | --- |
| 符号旋转 | 48 个器件按 0° 一字排开会严重重叠、导线穿插 | 全部 |
| 网络标签 | GND 有 31 个节点，靠实体导线连会乱成一团 | power / mcu / rtc |
| 派生符号展平 | AMS1117-3.3、AO3400A 自身无引脚 | power / led |

（第三项已在 `symbol_lib.py` 中实现，前两项待做。）
