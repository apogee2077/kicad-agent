# 预验证积木（**必须优先使用**）

## 积木使用规则

1. 只要电路里出现 LED，**必须**通过 `circuit_blocks` 声明 `led` 积木，
   并且**不要再**为这颗 LED 及其限流电阻写任何 `nets`。
2. `gpio` 必须是 BOM 中真实存在的引脚节点，例如 `"U1.10"`。
3. 积木会自动分配位号（电阻用 R、LED 用 D），你不需要指定位号。
4. 积木展开出的元件会自动加入 BOM，**不需要**在步骤 02 里预先列出。

# 硬约束（违反任意一条即为无效输出）

1. 引脚号必须**逐字**来自上表。表中没有的引脚号一律不得出现。
2. 上表里每个器件的每个引脚，必须**恰好**属于以下之一：某个 `net`，或 `no_connect`，
   或由积木自动处理。不得遗漏。
3. 同一引脚不得出现在两个不同的网络里。
4. 电源网络统一使用 `+5V`、`+3V3`、`GND` 三个名字。其余网络用大写字母加下划线，语义化命名（如 `I2C_SDA`、`LED_PWM`、`BTN_SET`）。
5. 每个 `net` 至少 2 个引脚。
6. 芯片未使用的引脚必须列入 `no_connect`，**不要**接到 GND，也不要建空网络。
7. 不要凭芯片手册记忆去连，只按上表给出的引脚名判断功能。

# 关于 erc_power_flags

`erc_power_flags` 只列**有电源输入脚、却没有电源输出脚驱动**的网络。

- LDO 的**输出**网络由 LDO 自己驱动，**不要**列入。
- 接插件输入的电源网络（无源器件驱动不了）**要**列入。
- 电池经二极管供电、给芯片 `Power input` 脚的网络**要**列入。

# 输出格式

只输出一个 JSON 对象。**不要**围栏、**不要**解释，第一个字符必须是 `{`。

```
{
  "circuit_blocks": [
    {"type": "led", "gpio": "U1.10", "color": "Red", "resistor": "220"}
  ],
  "nets": [
    {"name": "I2C_SDA", "nodes": ["U2.33", "U3.15"]}
  ],
  "no_connect": ["U2.4"],
  "erc_power_flags": ["+5V", "GND"]
}
```

# 输出前自检

3. 有没有同一引脚出现在两个网络？
4. 有没有芯片的电源脚悬空？

6. **所有 LED 是否都用了 `led` 积木？有没有又手写了一遍 LED 与电阻的连线？**
